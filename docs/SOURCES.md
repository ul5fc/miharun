# 情報源について（SOURCES.md）

miharun が使うすべての情報源の一覧です。
いずれも「公開情報を読むだけ」のものです。

## 1. 証明書透明性ログ — crt.sh

| 項目 | 内容 |
|---|---|
| 提供元 | crt.sh（Community / Sectigo 系） |
| サイト | https://crt.sh/ |
| 使う API | `https://crt.sh/?q=%.<domain>&output=json` |
| 得られるもの | 発行済み TLS 証明書のホスト名一覧（サブドメインの候補） |
| 制限 | 混雑時に HTML を返すことがある（リトライ対応済み） |

### 仕組み

TLS 証明書には「どのホスト名に対して発行されたか」が記録されます。
証明書は信頼できる認証局から発行されるため、このログは信頼性の高い
Attack Surface 情報源です。

`*.example.com` というワイルドカード証明書が発行されている場合、
`example.com` 以下のホストがまとめて現れます。

### 注意

- ログに載っている＝現在も生きている、とは限りません。別途確認が必要です。
- 得られるのは証明書が発行された時点のホスト名です。

## 2. DNS over HTTPS

| 項目 | 内容 |
|---|---|
| 提供元 | Cloudflare / Google |
| エンドポイント | `https://cloudflare-dns.com/dns-query`<br>`https://dns.google/resolve` |
| 得られるもの | A / AAAA / CNAME / MX / TXT / NS / PTR |
| 送信先 | DNS リゾルバのみ。対象ホストではない |

### なぜ HTTPS で DNS を引くのか

通常の DNS（UDP 53）は経路で書き換えられる場合があります。
DoH は TLS で保護されているため、判定に使う情報として信頼できます。

**技術的な必然性ではなく、判定の信頼性のための選択です。**
UDP でも動作しますが、判定を誤ったときに
「DNS のせいだ」と言えることは価値があります。

### なぜ pip パッケージを使わないのか

`dnspython` を使えば簡単ですが、**依存ゼロで動くこと**を優先しました。
`git clone` した直後に `python -m miharun` で動かせることは、
「ちょっと試す」というハードルを大きく下げます。

### よく使うレコード

| レコード | 使い道 |
|---|---|
| `NS` | DNS プロバイダの判定（Cloudflare / お名前.com / さくら など） |
| `MX` | メールプロバイダの判定（Google Workspace / Microsoft 365 など） |
| `TXT` | SPF・DMARC。所有確認 TXT から利用 SaaS を判定 |
| `CNAME` | CDN・静的ホスティングの判定（CloudFront / Vercel / GitHub Pages など） |
| `PTR` | IP を運用している組織（sakura.ne.jp など）を判定 |

## 3. 法人番号システム Web-API（国税庁）

| 項目 | 内容 |
|---|---|
| 提供元 | 国税庁 法人番号公表サイト |
| 申込先 | https://www.houjin-bangou.nta.go.jp/webapi/ |
| 費用 | 無料（利用申請書の提出が必要） |
| 環境変数 | `HOUJIN_APP_ID` にアプリケーションIDを設定 |
| 得られるもの | 法人番号・法人名・所在地 |

### 仕様メモ

- エンドポイント: `https://api.houjin-bangou.nta.go.jp/4/name`
- 必須パラメータ: `id`（アプリケーションID）、`name`（法人名）
- 応答は **CSV または XML**。miharun は両方に対応しています

## 4. gBizINFO API（経済産業省）

| 項目 | 内容 |
|---|---|
| 提供元 | 経済産業省 gBizINFO |
| 申込先 | https://info.gbiz.go.jp/ |
| 費用 | 無料（利用申込みが必要） |
| 環境変数 | `GBIZINFO_TOKEN` に API トークンを設定 |
| 得られるもの | 法人情報 **と 企業URL**（公式サイトのドメイン） |

### なぜ gBizINFO を優先するか

法人名からドメインを決めるには「公式サイト URL」が必要です。
gBizINFO は企業URLを返せるため、この用途では
法人番号 API より直接的に求められます。

使用エンドポイントは `https://api.info.gbiz.go.jp/hojin/v2/hojin` で、
失敗した場合は `https://info.gbiz.go.jp/hojin/v1/hojin` にフォールバックします。

## 5. 使っていないもの（意図的）

| 手段 | 使わない理由 |
|---|---|
| ポートスキャン | 攻撃的な操作。守る側のツールには不要 |
| 総当たり攻撃 | 同上 |
| 検索エンジンのスクレイピング | 利用規約に抵触する恐れがある |
| 有料 API | 有料では「誰でも無料で試せる」にならない |
| 機械学習による推定 | 根拠を追えなくなる。追跡可能性更重要 |

## 6. 出典を明記する理由

**推測を推測で固めないためです。**

miharun の出力は、どのレコードのどの文字列から判断したかを
たどれるようにしています。推定が外れたとき、
「情報源が変なのか」「判定ルールが変なのか」を切り分けられます。

> 出典を追えない情報は、確認にも反論にも使えません。
