# 利用にあたっての安全性（SAFETY.md）

miharun は「守る側」のツールです。設計のすべての判断は、
次の 1 つの考え方に基づいています。

> 公開されている情報があるなら、公開されている経路から読む。
> それがなければ、入手しようとはしない。

---

## 1. パッシブ・ファースト

miharun の既定の動作では、対象ホストにリクエストを一切送りません。

| 情報源 | 実際にアクセスする先 | 対象への送信 |
|---|---|---|
| 証明書透明性ログ（crt.sh） | crt.sh | なし |
| DNS over HTTPS | Cloudflare / Google の公開リゾルバ | なし（通常の DNS 引きと同じ） |
| 法人番号 / gBizINFO | 各省庁の公開 API | なし |
| 逆引き（PTR） | Cloudflare / Google の公開リゾルバ | なし |

DNS の問い合わせ先は「対象のサーバー」ではなく「DNS リゾルバ」です。
ドメイン名を Whois で調べるのと同じ性質の操作で、
常に合法な受動的な操作にすぎません。

---

## 2. やること・やらないこと

### 行うこと（すべて受動的）

- 証明書透明性ログの閲覧
- DNS レコードの取得（A / AAAA / CNAME / MX / TXT / NS / PTR）
- 公開されている API への問い合わせ
- 取得した情報の整理と日本語での要約

### 行わないこと（実装していません）

- ポートスキャン
- 総当たり攻撃（ブルートフォース）
- 大量リクエスト・負荷の生成
- ログイン試行・認証情報の推測
- 脆弱性の攻撃的な検証
- 取得したデータの保存・二次配布

引数として `--port-scan` のようなフラグは存在しません。
実装しても作りません。

---

## 3. `--probe` の扱い

`--probe` を指定した場合に限り、対象ホストに HTTP で 1 回だけアクセスします。

守るルールは次のとおりです（すべて `src/miharun/sources/http_probe.py` に実装）。

1. **既定では無効。** 明示的に指定した場合のみ
2. **robots.txt を確認し、拒否されていればアクセスしない**
3. **1 ホストにつき 1 回。** アクセス間隔は 1 秒
4. **対象は最大 50 ホストまで**
5. **応答本文は先頭 64KB しか読まず、保存しない**
6. 取得するのは `Server` ヘッダ、`<title>`、CMS 判定用の目印のみ

### 存在しないフラグ

```
miharun example.com --port-scan      # 実装なし
miharun example.com --brute          # 実装なし
miharun example.com --exploit        # 実装なし
miharun example.com --threads=100    # 実装なし
```

---

## 4. `--probe` を使ってよい場面

```
OK   自分のドメイン、自分のサーバー
OK   クライアントと契約して状況確認を委任された対象
OK   バグバウンティプログラムで scope として明記された対象
OK   学校や社内の練習環境

NG   他人が管理しているサーバー
NG   「気になるから」で調べた第三者のサイト
NG   バグバウンティの scope 外のドメイン
```

---

## 5. 「許可なく調べた」という主張について

**許可を得ずに得られる情報が、存在しないわけではありません。**

- 証明書透明性ログは**公開の記録**です。読むだけなら許可は不要です。
- DNS 引きは**Whois と同じ**扱いです。

ただし、**見つかった情報を攻撃に使うことは別の問題です。**
miharun は守る側の作業を支えるための道具であり、
侵入するための道具ではありません。

---

## 6. 見つけた情報の扱い

- 生成されたレポートはローカルに保存されます（既定 `out/`）
- 自分以外への公開や送信は行わないでください
- スクリーンショットの共有は、対象機関の許可を得てから

---

## 7. 不適切な公開状態を見つけたとき

miharun で「外部に公開されているが、管理されていない」状態を見つけた場合、
その対象に侵入するのではなく、**所有者へ報告するのが正しい対応です。**

- 不具合があれば、それを所有する組織へ報告する
- バグバウンティの窓口があるなら、そちらへ報告する
- **推測だけで悪用しない**
